# Формат `.axon`, версия 3

UTF-8 JSON, самодостаточный файл. Верхний уровень: `format: "axon"`, `version: 1 | 2 | 3`, `id`, `title`, `background`, `objects`, `assets`. Порядок объектов задаёт порядок от заднего к переднему плану. Новые документы имеют версию 3. Версии 1 и 2 читаются без изменения внешнего вида; первое изменение в редакторе переводит документ в версию 3. Неизвестная версия отклоняется.

Общие поля объекта: `id`, `type`, `x`, `y`, `w`, `h`, `locked`, необязательный `groupId`, `style`. Координаты мировые. `groupId` — плоская группа, блокировки её членов согласованы.

| Тип          | Дополнительные поля                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------ |
| shape        | `shape`: rect / ellipse / diamond / triangle / database / callout; `text`; необязательный `mind` |
| sticky, text | `text`                                                                                           |
| stroke       | `points`: координаты относительно x/y; фактические границы вычисляются по точкам                 |
| image        | `assetId`                                                                                        |
| connector    | `start`, `end`, `route`, `arrows`, `text`; необязательные `mindBranch`, `startMarker`, `endMarker` |

Конец связи: `{type:"free",x,y}` или `{type:"bound",nodeId,side}`. Стороны top/right/bottom/left, цели — shape/sticky. `route`: straight/orthogonal/curved, `arrows`: none/end/both. Общие x/y/w/h связи не являются её маршрутом. Привязки вычисляются по актуальному силуэту, поэтому движение узла не записывает производные координаты в связь.

Совместимое расширение читаемой модели: `startMarker?`/`endMarker?` независимо принимают `none | arrow | open | triangle | circle | diamond`. Явное поле имеет приоритет только для своего конца. При отсутствии полей `arrows:none` означает none/none, end — none/arrow, both — arrow/arrow. Загрузка не добавляет поля и не меняет вид/толщину старого файла. При выборе окончания записывается только соответствующее поле; ID, start/end, подпись и маршрут сохраняются. Версия записи остаётся 3, старые файлы 1/2/3 читаются. Старые сборки со strict-схемой без этих дополнительных полей не смогут открыть документ с новыми окончаниями; обратная запись для них не заявляется. Preferences.connector использует те же необязательные поля, старые настройки не сбрасываются.

Стиль: `fill` (hex или none), `stroke`, `strokeWidth`, `dash`, `radius`, `color`, `fontSize`, `font` (sans/mono), `align` (left/center/right), необязательный `padding`. Отсутствующий padding соответствует прежним 18 единицам; у самостоятельного текста внутренний отступ нулевой. При общей трансформации padding/шрифт масштабируются с геометрией. Цвета сохраняются независимо от темы. Новая обводка фигур — 1,5; существующие strokeWidth сохраняются до явного сброса. Поле не удалено: оно нужно legacy, соединениям и карандашу.

`mind` содержит `{treeId,parentId,order}` и необязательные в v3 `side`/`presentation`: treeId — ID корня, parentId — ID родителя или null у корня, order — неотрицательный порядок соседей. Структурный connector хранит `mindBranch` — ID дочерней темы; start привязан к её родителю, end к ребёнку. Проверяются циклы, принадлежность дереву, существование корня и ровно одна структурная связь некорневой темы. Отдельная обычная стрелка не создаёт родство.

`assets` — словарь `{id,mime,data,width,height}`, base64 без URI-префикса. PNG/JPEG встроены; новые импорты нормализуются в PNG. Файл не зависит от оригиналов изображений. Удаление очищает неиспользуемые ресурсы, предыдущие snapshots Undo сохраняют свои assets.

В v3 `mind.side?: "left" | "right"` хранит направление, `mind.presentation?: "text"` включает текстовое авторазмерное представление. Текстовое представление требует стороны; потомок некорневого узла наследует его направление. Новые темы записывают оба поля. Legacy mind без presentation сохраняет внешний вид; старое направление читается из endpoint структурной связи, не из близости объектов. Обычные фигуры не превращаются в дерево. Новые поля в v1/v2 отклоняются как несогласованная версия. Толщины/цвета старых объектов и настройки инструмента сохраняются.

## Валидация и лимиты

Zod strict проверяет весь документ до открытия: неизвестные типы/поля, дубли ID, висячие привязки, неподходящие цели, отсутствующие assets, группы и дерево. Неизвестная фигура не становится прямоугольником. Числа конечны, цвета — `#RRGGBB`, исполняемого содержимого и удалённых URL нет.

- Файл до 80 МБ, объектов до 10 000.
- Координаты ±1 000 000, сторона 1–100 000.
- Текст до 20 000 символов; размер шрифта 1–1200 для пропорциональных трансформаций, padding 0–10 000.
- Штрих до 50 000 точек, толщина до 24.
- Импорт изображения до 20 МБ, 16 384 по стороне, 40 мегапикселей.
- Экспорт до 16 384 px по стороне и 64 мегапикселей при выбранном масштабе.

В переносимый `.axon` не входят вкладки, пути файлов, камера, выделение, активный инструмент, жест, Undo, тема, сетка и defaults. Старые версии приложения не обязаны открывать v3. Отдельной разрушительной миграции стилей нет.

## Рабочая сессия и восстановление

В userData `recovery.json` хранит `{activeId,tabs}`. Каждая вкладка содержит sessionId, document, path, savedContent, fingerprint, признаки состояния и необязательные untitledName (временная подпись) и view (camera/selection). Session ID отделён от ID переносимого документа. savedContent — точная сериализация снимка последнего ручного сохранения, fingerprint — SHA-256 прочитанных/записанных байтов файла. При асинхронной записи новые изменения остаются dirty. Наличие пути не означает доступности исходного файла: рабочая копия сохраняется отдельно.

documentName получает имя из path/untitledName одной записи session ID. Legacy title не задаёт вкладку/header/системный title. Без view камера начинается с zoom=1.

Это служебный формат, не `.axon`. Читается прежняя рабочая копия `{document,path,saved,at}`; неизвестный старый отпечаток требует безопасного Save As при конфликте. Preferences/recents/workspaceFolder записываются в settings.json. Undo между запусками не сохраняется. Явно закрытые с отбрасыванием вкладки исключаются из recovery; их файлы не удаляются. Recovery гарантирует последнюю завершённую запись, не события после неё.
